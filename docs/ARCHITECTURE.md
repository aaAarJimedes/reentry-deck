# 架构说明

## 边界

复航台是“工作上下文恢复器”，不是通用待办清单。它只保存用户明确留下的证据，不自动推断完成度，不监听其他应用，也不把工作轨迹发送到外部服务。

## 分层

```text
src/ui/app.js
  页面投影、事件委托、对话框、键盘与焦点
        ↓
src/core/session.js + capture.js + reentry.js + search.js + insights.js + import-preview.js + timeline.js
  会话不变量、应急停靠、快捷捕获、复航卡、排序、搜索、链接识别、工作区洞察、导入差异与 DOM 集合窗口纯函数
        ↓
src/core/model.js
  工厂、归一化、导入前校验和数据枚举
        ↓
src/core/store.js
  两阶段本地保存、冲突检测、标签页同步、备份信封
```

`sw.js` 只缓存应用外壳，不接触业务数据。`tools/server.mjs` 只公开运行应用必需的白名单文件，仓库元数据、测试和工具文件不会通过 HTTP 暴露。

## 关键不变量

1. 同一时间最多一个活动会话。
2. 检查点只引用存在的项目与会话。
3. 快速停靠不声称工作已经完成；其会话状态为 `abandoned`，并记录明确的关闭原因。
4. 快速停靠只能读取同一项目、同一会话的面包屑。
5. 导入先检查集合形状、ID、引用和枚举，之后才允许归一化。
6. 保存前比较当前浏览器存储与本页已知快照；不一致时采用外部新版本并拒绝本次旧写入。
7. 回滚副本属于增强保护，绝不能在容量临界时阻止主数据的原子替换。
8. 复航投影按证据时间选择摘要与下一动作；旧检查点不能覆盖更新的轨迹，已解决信号不能进入未决清单。
9. 检查点后的活动或中断会话构成“现场缺口”，必须降低而不是提高复航完整度。
10. 工作区统计只使用显式时间戳；异常长单段会话的计入上限为 12 小时，界面必须披露这一边界。
11. 撤销从滚动快照恢复，但新修订号必须高于当前状态；恢复写入仍接受同一套多标签冲突保护。
12. 导入预览必须先完成严格校验且不写入；确认时若当前状态已变化，必须重算差异并要求再次核对。
13. 项目页只渲染最近 30 条轨迹；展开以固定批次增加，但全量记录始终参与搜索、统计和备份。
14. 主数据、跨标签写入、滚动快照和导入文件共用严格校验：引用必须同项目一致，时间与文本必须在安全边界内。
15. 从损坏主数据恢复后，第一次成功保存不得把损坏原文写入滚动快照；上一份有效恢复点必须继续保留。
16. 置顶只创建可解释的复航投影，不改变时间线顺序、证据时间或下一步优先级；复航卡最多展示三条。
17. 快捷捕获只关联目标项目自己的活动会话；没有活动会话时保存为项目级证据，绝不借用其他项目的会话。
18. 搜索与命令共用同一对话框，但动作只通过既有应用方法执行；空查询显示命令，非空查询始终只产生只读证据结果。
19. 无效的跨标签写入必须保持当前有效状态并触发一次可见通知；同一损坏原文不得反复刷新或堆积告警。
20. 存储订阅区分本地与外部提交；只有外部刷新可短暂保存并恢复普通对话框状态，文件输入、隐藏标识与已经失效的选项不恢复。
21. 项目舰桥和归档舱首屏各最多渲染 12 张项目卡，展开以固定批次增加；完整推荐排序、概览统计与所有持久化数据不受窗口影响。
22. 多项目复航投影先按项目 ID 一次性索引会话、轨迹、检查点与最后活动时间；推荐、周内完整度与关注清单不得为每个项目重复过滤全量集合。
23. 搜索索引按不可变状态对象惰性建立并复用；空查询不建索引，状态身份变化后才重建，查询只为实际匹配项分配结果对象。
24. 新备份信封对数据对象的确定性 UTF-8 JSON 表示计算 FNV-1a 32 位校验码；它只检测意外损坏，不提供加密认证，旧信封仍按“未验证”兼容。
25. 主数据写入仅在明确的配额异常且滚动快照存在时允许释放快照重试一次；其他错误不清理，重试失败必须尽力恢复快照且不得提交内存状态。
26. 短时操作反馈以带到期时间的内存队列为事实源；DOM 重建只重新投影未到期项目，原定时器负责从队列和当前 DOM 同时清除。
27. 归档属于可逆但会改变项目可写性的操作；必须先在应用内对话框展示准确项目名与保留范围，默认焦点停在取消动作，并在确认时重新检查项目与活动会话状态。
28. 备份文件在读取和 JSON 解析前必须通过可信整数大小检查，超过 25 MB 直接拒绝；同一不可变状态版本的备份大小只计算一次，界面重投影不得重复克隆整份工作区。
29. 点击、变更和键盘命令的同步调用必须经过统一用户操作边界；业务错误、配额异常和多标签冲突不得逸出为无反馈的事件异常，异步导入继续在自身边界收敛。
30. 从 `src/main.js` 可达的每个本地模块必须同时存在于服务器白名单和离线外壳；两份运行时清单除服务工作线程本身外必须集合相等，发布版本在包元数据、备份信封与最新版本记录中一致。
31. 应用销毁必须幂等释放根节点/窗口事件、存储订阅、跨标签监听、周期计时器和待处理提示定时器；销毁后的外部存储事件不得再次投影旧实例。
32. 离线外壳安装使用 Cache API 原子批处理；任一网络响应或缓存写入失败时整批不得可见，旧服务工作线程和完整缓存继续承担回退。激活只清理本应用旧版本缓存。
33. 导航与已知运行时资源采用 network-first/stale-if-error：网络 200 优先且缓存刷新只尽力执行，404/5xx 或网络异常回退已有规范 URL 缓存；未知且未缓存资源保留原 HTTP 失败。
34. 复航资源只接受不含凭据的 HTTP(S) URL，原文和解码目标不得含 ASCII/双向/不可见控制码，规范化前后均不超过 2,048 字符；外链使用独立标签、断开 opener 并提供明确可访问名称。
35. 本地服务器对所有响应统一设置最小权限 CSP、空摄像头/麦克风/定位权限、同源资源策略与防嵌入头；白名单仍是可公开文件的最终边界。
36. 所有导入与持久化时间必须满足 `new Date(Date.parse(value)).toISOString() === value`，即规范 UTC、固定毫秒精度；自然语言、地区格式、时区偏移和省略毫秒的可解析字符串仍视为无效。
37. 新写入时间取“系统当前时间与业务锚点中的最大值”：工作区元数据不早于上一修订，项目变化不早于自身更新时间，会话证据/检查点不早于会话与项目锚点，解决时间不早于原记录；系统时钟回拨不得制造倒序证据。
38. 严格导入验证跨记录因果区间：来源检查点不晚于接续会话开始，结束检查点与会话内轨迹/检查点落在开始和可选结束之间，解决时间不早于记录，活动会话不含结束检查点。
39. 所有持久化提交的修订号为 `max(当前修订, 来稿修订) + 1`；外部有效状态只有修订号严格前进时才采用。主键被显式移除时生成更高修订号的空工作区，避免版本序列归零。
40. 存储监听同时处理主键事件与 `key === null` 的全量清空事件，并在浏览器提供 `storageArea` 时校验事件来源，避免遗漏 `localStorage.clear()` 或误采用其他存储区事件。
41. 跨标签状态采用同时要求修订号严格增加且工作区 `updatedAt` 不早于当前状态；高修订号不能成为时间倒退的旁路。
42. 本地容量展示遍历当前来源的存储键值，按 DOM Storage 的 UTF-16 字符估算整个来源及 `reentry-deck/` 自有占用；以 5 MiB 作为明确标注的保守参考线而非伪造浏览器真实配额，80%/100% 分级预警。
43. 50,000 条总记录安全上限属于基础状态不变量，导入、替换和本地更新在持久化前共享该边界；超限时先返回单一容量错误，不遍历异常大的记录集合。
44. 哈希路由只接受 `#/`、`#/archive`、`#/settings` 与单段 `#/project/:id`；项目段在解码前后分别受 2,400/200 字符上限约束，畸形编码、控制字符、额外段和未知路由统一进入未找到页。
45. 严格备份要求工作区创建时间不晚于更新时间；项目更新时间不早于创建时间，项目自身辅助时间及所属会话、轨迹、检查点均落在项目创建—更新窗口。快速停靠并接续时，元数据时间推进到晚 1 ms 的接续会话开始。
46. Service Worker 的在线导航与外壳资源请求使用 4 秒 `AbortController` 超时；超时与网络异常共享缓存回退，成功/失败路径都清理计时器，避免弱网悬挂和长期资源泄漏。
47. 本地服务端口只接受去除首尾空白后的完整十进制 0–65535；白名单文件的 `stat` 失败统一转为 404，GET/HEAD 与文本错误都返回准确 `Content-Length`，避免宽松配置和探测竞态终止服务。
48. 复航缺口完全由当前派生证据生成，不写入状态：优先提示未收拢会话与快速停靠复核，再指出缺少摘要、下一动作、可靠检查点或材料入口；完整卡片不显示空提示框。
49. 快速检查点复核要求提交时目标仍是该项目的最新快速检查点，并拒绝摘要/下一动作的“未记录”占位；保存为 `sessionId: null` 的新人工检查点，原会话结束检查点及历史记录保持不变。
50. 复航索引与时间线按时间倒序；合法时间相同则以状态数组中更晚的插入为更新证据。界面开始会话和复核检查点必须复用该索引，不能自行定义“最新”排序。
51. `AppStore.update()` 在序列化前执行与导入候选相同的严格内容、引用、枚举和因果时间校验；配额与多标签保护之前不得产生一份“当前可写、重启即损坏”的本地主数据。
52. 轨迹是原始证据，项目动作和快速检查点是受字段上限约束的派生投影；超长投影以省略号明确压缩而不改写原轨迹，快速停靠的未决事项只收集尚未解决的问题与阻塞。
53. 界面 `maxlength` 必须直接投影 `IMPORT_LIMITS`，不得复制数字边界；自动压缩按完整 Unicode 码点累计并仍以 UTF-16 字符上限为最终容量约束，不能切出孤立代理字符。
54. 备份文件读取使用“最新请求获胜”门闩；选择新文件或销毁应用会使旧异步完成失去提交资格，过期结果不得改写待导入预览、提示或当前控件。
55. 离开提醒阈值是 1–365 天的持久化数字设置；界面常用选项不得丢弃导入的其他合法值，关注清单每次从当前状态派生而不缓存旧阈值结果。
56. `reducedMotion: false` 表示跟随系统媒体偏好，`true` 表示应用内强制减少；每次投影都把状态写到根节点数据属性，CSS 两条路径共享相同的动画、过渡和滚动降级边界。
57. 主题外观由持久化模式和当前 `prefers-color-scheme` 共同解析；只有 `system` 读取媒体查询，显式主题覆盖系统。媒体查询监听必须随应用实例创建和释放，并同步 `meta[name=theme-color]`。
58. 根级键盘处理在解释任何全局命令前先检查打开的 `dialog`；模态存在时不打开第二模态、不导航、不撤销后台状态，未阻止默认行为的 Escape 继续交给浏览器原生对话框语义。
59. 所有面向界面的定长文本投影复用 `compactText`：搜索摘要先折叠空白再压到 150 个 UTF-16 单元，备份版本元数据压到 80 个单元；省略不能拆分 Unicode 码点。
60. 备份下载的临时链接在点击期间必须接入文档，点击后延迟一个有界窗口再撤销对象 URL；点击或调度异常则同步移除节点并撤销 URL，成功与失败路径都只释放一次。
61. 持久化文本拒绝零宽空格、方向标记、双向覆盖/隔离、字节序标记及除换行/回车/制表外的 C0/C1 控制字符，但保留文字塑形与组合 emoji 所需的 ZWNJ/ZWJ；ID 使用更严格边界。可选信封展示元数据含危险字符时降级为不显示。
62. 资源 URL 的原文与解码路径、项目哈希路由的解码 ID 和持久化 ID 复用同一严格控制字符判定，覆盖完整 C0/C1、零宽、方向与双向控制区，编码形式不得绕过。
63. 状态根、`meta`、`settings`、`ui` 与四类记录必须是原型为 `Object.prototype` 或 `null` 的普通对象；带 `toJSON` 或特殊结构化克隆语义的对象必须在序列化前拒绝，不能产生只在重启后暴露的形状损坏。
64. 默认存储属性访问与每次主键读取都视为可失败：启动拒绝时降级为带通知的不可保存临时工作区；外部读取失败保持当前状态；保存前读取失败禁止覆盖；恢复点不可读不得遮蔽原主数据错误。
65. `AppStore` 对外发布的状态冻结根、三个容器、四个集合及每条扁平记录；界面以稳定对象身份建立派生缓存，所有写入只能在结构化克隆配方中发生并在持久化成功后替换不可变快照。
66. 状态发布遍历发送开始时的订阅快照并逐个隔离异常；订阅失败不得逆转、遮蔽或误报已经完成的持久化提交，不得阻断其他订阅者，同一回调的故障诊断只排入一次。
67. 复航简报是当前复航卡的无状态纯文本投影，不写入工作区；未决文本按模型边界压缩。复制优先 Clipboard API，回退控件无论成功失败都移除，并发/销毁后的旧异步完成不得反馈。
68. 复制回退在选择隐藏文本域前记录原焦点及文本选区，并在所有退出路径尽力恢复；临时节点清理或原控件失效不得遮蔽复制操作本身的结果。
69. 简报的“未决事项”以实时未解决的问题/阻塞为准，不得被旧检查点覆盖；仅剩检查点自由文本时必须标为历史待确认。简报同时携带经夹取的完整度与可执行证据缺口。
70. 离线外壳安装仍要求原子完整预缓存；激活后的请求路径则把 CacheStorage 视为可失败的加速层。运行时打开、读取或写入缓存失败不得遮蔽可用网络响应，网络与缓存同时不可用时返回明确 503。
71. 在线导航/外壳请求与运行时缓存打开并行，成功网络响应不等待缓存；fetch 事件在同步分发阶段先登记聚合生命周期，稍后产生的刷新任务只能加入该生命周期，不得延迟调用 `waitUntil()`。运行时缓存打开最多等待 750ms。
72. 本地 HTTP 服务仅接受以单斜杠开头、无片段和控制字符的 origin-form 请求目标；绝对 URL、网络路径、原始/解码 C0/C1 控制字符在 URL 解析前后均返回 400，查询参数不参与静态文件映射。
73. 静态响应先打开文件描述符，再从同一描述符确认普通文件与长度，并把读取上界固定为该快照大小；路径替换或后续增长不得越过已发送的 `Content-Length`。HEAD、零字节、拒绝和中断路径都关闭描述符。
74. 备份读取优先使用 Blob 字节流，逐块累计实际字节并在 25MB 后立即取消；新选择和应用销毁主动中止旧读取。无流环境才回退 `text()`，并在解析前以无额外大缓冲的 UTF-8 计数复核实际大小。
75. 导入预览保留首次校验产生的规范化快照及独立的信封来源证据；旧格式缺省时间只在此刻补齐。工作区变化后重新比较、最终确认与失败重试都引用该快照，且不得丢失版本、导出时间或校验结果；只有新提交元数据按确认时刻前进。
76. 每次主存储提交先取得 5 秒同源写租约（随机所有者、绝对过期时间），读取主基线、主写及配额重试都在该租约内；写前必须同时复核令牌所有权与未过期。并发标签页只能有一个提交，页面长暂停后的旧租约不得继续写，释放只删除自己的令牌。
77. 活动会话的陈旧签名由会话 ID、当前陈旧原因与用户确认态组成；每秒计时刷新只在签名跨越 12 小时/自然日边界时重绘一次。若焦点仍在输入控件则延后重绘，避免丢失未提交文本；对话框重绘使用现有瞬态恢复。
78. 设置分段按钮以有名称的 `group` 暴露；重复的证据解决/置顶、项目恢复和简报复制动作把所属证据或项目加入可访问名称。动态上下文折叠空白并按 80 字符 Unicode 安全压缩，视觉标签保持短促。
79. 对话框瞬态恢复分别保存字段快照与全部可聚焦控件位置；外部状态或会话生命周期重绘后，按钮焦点、字段值及文本选区各按类型恢复。导入预览也参与该机制，失效/禁用目标不强制聚焦。
80. 搜索查询在比较任何候选前同时限制原文/规范化总长、去重词元数量与单词元长度，越界整次拒绝而非截断语义；资源主机在安全校验后移除 DNS 尾点再去重，路径与查询参数不作等价猜测。
81. 周报会话集合按 `[startedAt, endedAt/now]` 与回顾窗口的区间交集选取，恰在窗口起点结束不计入；时长先夹到窗口，再对每段应用 12 小时异常上限。会话计数、切换与关闭原因必须复用该集合。
82. 首页排名、周报复航完整度与关注清单共享同一时刻的一批未归档复航卡，证据集合只建立一次索引；“显示更多”只扩展持久化于界面实例的窗口，不允许预先重复全量派生来计算数量。
83. 复航卡的结构化问题/阻塞是当前未决事实；仅存在检查点自由文本时，它只能作为“曾记录、待确认”的历史线索展示。实时信号覆盖历史文本，快速停靠的未记录占位不进入历史投影，屏幕与纯文本简报必须一致。
84. 归档舱只为当前集合窗口批量建立一次复航索引，并在一次轨迹遍历中汇总可见项目计数；不得在卡片映射内部调用单项目全量索引或按项目重复过滤全轨迹集合。缺失派生卡必须使用明确摘要缺省。
85. 复航索引接收明确目标项目集合；遍历全局记录只允许读取关联 ID 来筛选，时间/正文载荷及排序数组只为目标项目建立。单卡、批量卡与未归档排名分别传入最小目标集合，输出顺序和缺失 ID 语义保持稳定。
86. 单项目时间线在全局扫描中先按项目 ID 筛选再分配排序条目；项目统计对会话、轨迹、检查点各执行一次流式遍历并在同一分支累计分类值。无关记录不得产生排序包装，统计不得嵌套集合过滤。
87. 备份校验可持有规范 JSON 字符串，但不得再复制整份 UTF-8 字节数组；UTF-16 代理对按 UTF-8 四字节编码，结果必须与 `TextEncoder` 逐字节 FNV-1a 相同。导入项目差异只保留有界详情，总数在流式扫描中独立累计。
88. 备份字节流必须以有状态且 fatal 的 UTF-8 解码器处理；跨块多字节序列允许续接，非法续字节、过长/错误序列与末尾截断必须拒绝，禁止用替换字符修复后进入 JSON 校验。无字节流的兼容回退仍受实际 UTF-8 大小复核。
89. Service Worker 安装继续以完整壳原子预缓存为发布门槛；安装成功后的激活清理只是尽力维护。缓存列表或任一旧壳删除失败不得拒绝激活，必须继续 `clients.claim()`；残留旧壳可在后续激活再清理。
90. HTTP 请求目标在任何 URL 构造或百分号解码前限制为 8,192 单元；超界返回 414，空字符串和非字符串返回 400。只有缺省 `null/undefined` 可映射根路径，所有错误响应继续带安全头、精确长度与 `no-store`。
91. 搜索输入在 IME 组合阶段不执行派生扫描，完成后的正常输入事件统一更新。所有跨记录最终并列排序使用明确 UTF-16 码元比较，不依赖 `localeCompare` 的主机区域设置；业务分数、时间与持久化插入顺序优先级不变。
92. 本地静态服务只接受白名单资源的规范明文路径；路径部分出现任何百分号编码都返回 400，避免同一文件产生 Service Worker 不识别的线上别名。查询字符串与前端哈希路由保持各自语义，不受此规则误伤。
93. 原生备份字节流同时受声明大小、25MB 总量与 16,384 次有效分块三重边界约束；零长度块视为无进度故障。解码字符串按约 64K 段归并，异常立即取消读取器，避免伪造大小或极碎流拖住主线程并放大临时对象数。
94. 自由文本中的资源 URL 把中日韩正文标点视为词法边界；国际化主机按标签判断，单个标签同时混入 ASCII 字母数字与非 ASCII 字符时保守拒绝，避免后续说明被 URL 解析器误当成主机并转成看似合法的 Punycode 站点。
95. 写租约的活性窗口必须同时满足 `now < expiresAt <= now + 5s`；远未来期限说明持久化值损坏或时钟发生回拨，必须视为陈旧。旧持有者也用同一边界在主写前自我失效，避免双写同时保留永久锁死恢复能力。
96. 前端哈希路由在正则替换、路径分段和百分号解码前执行 2,420 单元总预算；该预算覆盖模型允许的 200 单元 Unicode ID 编码，但拒绝用大量斜杠或无关尾部制造解析临时对象的畸形地址。
97. 归档舱把只读检查与状态恢复分成两个明确动作：卡片详情链接进入同一项目路由并由归档状态选择只读投影，恢复按钮才写入状态。两者必须携带项目上下文名称，避免读屏用户误把检查当成恢复。
98. `staleAfterDays` 是持久化的离散日数而非任意有限数，模型、导入与界面统一要求 1–365 的安全整数；任何小数、字符串或非有限值都必须在保存/替换前原子拒绝。
99. schema v1 对根、`meta`、`settings`、`ui`、项目、会话、轨迹和检查点实行显式字段白名单；未知字段必须报出所属对象并拒绝，不能在规范化时静默丢失，也不能借元数据/设置展开把未深冻结嵌套对象发布给订阅者。
100. 复航资源先按证据时间排序；时间相同时以可靠检查点、随记、项目字段为明确来源优先级，同类记录再以后写入者优先。无法解析的时间统一落到同一保守基线并沿用相同顺序，重复 URL 不得由较弱或较早来源抢占出处。
101. 结构校验与详细导入校验共享 50 条诊断预算，第 51 条只报告仍有更多问题并停止遍历；引用完整性只维护项目、会话、检查点三个单遍 `Map`，不为 50,000 条记录额外投影数组或并存等价 `Set`。
102. 应急停靠快捷键只在恰有活动会话且没有打开模态时拦截 `Ctrl/⌘ Shift S`，复用与按钮完全相同的低置信度检查点事务；命令面板只在可执行时展示该动作，所有重复停靠入口都带项目上下文可访问名称。
103. 校验后的状态规范化也用单遍循环同时建立输出集合与项目/会话 ID 索引；孤儿过滤和悬空会话清除不串联 `filter().map()`，也不为索引再投影 ID 数组，避免导入边界处与原始 JSON、校验索引、克隆和规范化副本叠加峰值。
104. 导入差异只比较 schema v1 已规范化的扁平记录，因此按自有字段和值逐项判断，不为每个同 ID 记录重复序列化长文本；项目的数量差异、顺序差异和最多六条可见明细共享同一对索引，不重复建立集合等长 `Map`。
105. Service Worker 的内部 4 秒网络控制器同时转发原始请求的取消原因，并在客户端已取消时直接拒绝；标签关闭或导航替换不再继续后台联网，也不把主动取消误判成离线而读取缓存。监听器和超时在所有路径释放。
106. 复航资源在读取证据时间、拼接检查点字段和分配排序条目前先检查大小写不敏感的 HTTP(S) 词法候选；无链接的长历史只做单遍扫描。单条文本使用惰性匹配迭代器，避免先物化全部候选再受全局 20 条上限截断。
107. 项目时间线单遍统计目标项目总量，并用最差项在根的有界堆只保留当前窗口 K 条；最终只排序 K 条而不是全部历史。合法时间同值仍以后写入优先，全部畸形时间仍按原持久化先写入顺序，分页总数和继续边界保持精确。
108. 全局搜索对所有候选单遍评分，但只在最差项在根的有界堆中保留最终 K 条；宽查询不再物化或排序全部命中。分数、时间与代码单元 ID 的确定性顺序不变，完整结果对象仅在最终 K 条排序后展开。
109. 搜索索引在项目单遍中同时建立引用 `Map` 与项目候选，不先投影项目键值数组；项目和检查点字段用固定参数直接拼接，不为每条记录创建短数组并过滤。索引候选仍是不可变快照，空字段与分隔符语义保持。
110. 周报窗口只物化必须按开始时间排序的相交会话；时长、封顶、关闭原因、活动数与临近项目切换在排序后一次累计，轨迹创建/决定/解决数一次累计。可恢复度、最投入项目与活动项目 ID 使用标量或单输出数组归约，不复制统计表再排序。
111. 注意力甲板直接消费共享复航卡片，并用最差风险项在根的有界堆只保留最终 K 项；不再复制非归档项目、建立卡片映射或全量排序全部正分风险。分数降序、较早活动优先和代码单元 ID 并列规则不变。
112. 复航卡对每个项目已按新到旧排列的轨迹只扫描一次，同时填充所有有界证据槽；项目索引的内部数组先反转再用稳定时间排序表达“同毫秒后写入优先”，不再为每条证据包装插入序号并二次映射。三源证据择新、活动日期、完整度和开放文本都用固定参数或标量累计。
113. 快速停靠在目标会话轨迹单遍中用标量选择摘要/下一步，并以有界堆保留最多 401 条最新未决证据；401 是单字符证据加分隔符刚好越过 800 字符持久化上限的最坏情况。文本拼接越界即停，既保持新到旧输出与 Unicode 安全截断，也不为 50,000 条历史建立包装、全量排序或巨型字符串。
114. 本地下载在成功调度后延迟回收对象 URL；链接移除与 URL 回收各自吞掉清理异常，保证两者互不阻塞，且清理失败不掩盖链接创建、点击或调度的首个业务错误。延迟回调也不得向事件循环泄漏回收异常。
115. 备份字节流只有在声明大小精确匹配、UTF‑8 尾部解码完成且文本段成功合并后才算完整；其他任何退出都通过一次性取消门闩停止底层读取，再尽力释放锁。取消/解锁故障不得覆盖容量、编码、流形态或主动中止的原始错误。
116. 项目推荐按分数降序、最后活动降序、代码单元 ID 升序形成全序，不借助宿主区域设置或输入数组顺序决定完全并列项。项目 ID 收集、卡片构建和推荐字段展开均单遍追加，避免源集合 `filter().map()` 与中间卡片二次投影。

## 数据持久化

主键为 `reentry-deck/state/v1`，内容带单调递增的 `meta.revision`。每次成功写入后尽力保存前一版本；浏览器配额不允许第二份完整副本时，主写入仍然成立。若已有滚动快照阻塞主数据增量，程序只在配额异常下释放它并重试一次，同时要求尽快导出；其他错误绝不借机清理。前一版本可用于一次可逆撤销，但长期可靠恢复仍依靠用户导出的 JSON 信封。新信封携带内容校验码，导入时在结构检查前核对；旧信封和原始状态保持兼容。严格导入上限为 50,000 条记录，字段长度与界面输入上限一致，详细错误最多展开 50 项。

跨标签页通过 `storage` 事件接收新版本，并以持久化原文比较作为最终覆盖保护；即使事件延迟，过期标签也无法静默覆盖新数据。订阅事件同时标记 `local` / `external` 来源，使界面只在外部投影刷新时以内存方式保留正在编辑的普通对话框。

## 离线策略

安装时事务式预缓存完整外壳。在线导航和运行时资源使用网络优先并更新缓存，因此代码变化不会因忘记修改缓存编号而长期滞留；断网时回退到最后一次完整缓存。新增核心模块时仍应同步加入预缓存清单，以保证首次安装后的完整离线能力。
