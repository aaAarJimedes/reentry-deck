# 架构说明

## 边界

复航台是“工作上下文恢复器”，不是通用待办清单。它只保存用户明确留下的证据，不自动推断完成度，不监听其他应用，也不把工作轨迹发送到外部服务。

## 分层

```text
src/ui/app.js
  页面投影、事件委托、对话框、键盘与焦点
        ↓
src/core/session.js + capture.js + reentry.js + search.js + insights.js + import-preview.js + timeline.js
  会话不变量、应急停靠、快捷捕获、复航卡、排序、搜索、链接识别、工作区洞察、导入差异与 DOM 集合窗口纯函数
        ↓
src/core/model.js
  工厂、归一化、导入前校验和数据枚举
        ↓
src/core/store.js
  两阶段本地保存、冲突检测、标签页同步、备份信封
```

`sw.js` 只缓存应用外壳，不接触业务数据。`tools/server.mjs` 只公开运行应用必需的白名单文件，仓库元数据、测试和工具文件不会通过 HTTP 暴露。

## 关键不变量

1. 同一时间最多一个活动会话。
2. 检查点只引用存在的项目与会话。
3. 快速停靠不声称工作已经完成；其会话状态为 `abandoned`，并记录明确的关闭原因。
4. 快速停靠只能读取同一项目、同一会话的面包屑。
5. 导入先检查集合形状、ID、引用和枚举，之后才允许归一化。
6. 保存前比较当前浏览器存储与本页已知快照；不一致时采用外部新版本并拒绝本次旧写入。
7. 回滚副本属于增强保护，绝不能在容量临界时阻止主数据的原子替换。
8. 复航投影按证据时间选择摘要与下一动作；旧检查点不能覆盖更新的轨迹，已解决信号不能进入未决清单。
9. 检查点后的活动或中断会话构成“现场缺口”，必须降低而不是提高复航完整度。
10. 工作区统计只使用显式时间戳；异常长单段会话的计入上限为 12 小时，界面必须披露这一边界。
11. 撤销从滚动快照恢复，但新修订号必须高于当前状态；恢复写入仍接受同一套多标签冲突保护。
12. 导入预览必须先完成严格校验且不写入；确认时若当前状态已变化，必须重算差异并要求再次核对。
13. 项目页只渲染最近 30 条轨迹；展开以固定批次增加，但全量记录始终参与搜索、统计和备份。
14. 主数据、跨标签写入、滚动快照和导入文件共用严格校验：引用必须同项目一致，时间与文本必须在安全边界内。
15. 从损坏主数据恢复后，第一次成功保存不得把损坏原文写入滚动快照；上一份有效恢复点必须继续保留。
16. 置顶只创建可解释的复航投影，不改变时间线顺序、证据时间或下一步优先级；复航卡最多展示三条。
17. 快捷捕获只关联目标项目自己的活动会话；没有活动会话时保存为项目级证据，绝不借用其他项目的会话。
18. 搜索与命令共用同一对话框，但动作只通过既有应用方法执行；空查询显示命令，非空查询始终只产生只读证据结果。
19. 无效的跨标签写入必须保持当前有效状态并触发一次可见通知；同一损坏原文不得反复刷新或堆积告警。
20. 存储订阅区分本地与外部提交；只有外部刷新可短暂保存并恢复普通对话框状态，文件输入、隐藏标识与已经失效的选项不恢复。
21. 项目舰桥和归档舱首屏各最多渲染 12 张项目卡，展开以固定批次增加；完整推荐排序、概览统计与所有持久化数据不受窗口影响。
22. 多项目复航投影先按项目 ID 一次性索引会话、轨迹、检查点与最后活动时间；推荐、周内完整度与关注清单不得为每个项目重复过滤全量集合。
23. 搜索索引按不可变状态对象惰性建立并复用；空查询不建索引，状态身份变化后才重建，查询只为实际匹配项分配结果对象。
24. 新备份信封对数据对象的确定性 UTF-8 JSON 表示计算 FNV-1a 32 位校验码；它只检测意外损坏，不提供加密认证，旧信封仍按“未验证”兼容。
25. 主数据写入仅在明确的配额异常且滚动快照存在时允许释放快照重试一次；其他错误不清理，重试失败必须尽力恢复快照且不得提交内存状态。
26. 短时操作反馈以带到期时间的内存队列为事实源；DOM 重建只重新投影未到期项目，原定时器负责从队列和当前 DOM 同时清除。
27. 归档属于可逆但会改变项目可写性的操作；必须先在应用内对话框展示准确项目名与保留范围，默认焦点停在取消动作，并在确认时重新检查项目与活动会话状态。
28. 备份文件在读取和 JSON 解析前必须通过可信整数大小检查，超过 25 MB 直接拒绝；同一不可变状态版本的备份大小只计算一次，界面重投影不得重复克隆整份工作区。
29. 点击、变更和键盘命令的同步调用必须经过统一用户操作边界；业务错误、配额异常和多标签冲突不得逸出为无反馈的事件异常，异步导入继续在自身边界收敛。
30. 从 `src/main.js` 可达的每个本地模块必须同时存在于服务器白名单和离线外壳；两份运行时清单除服务工作线程本身外必须集合相等，发布版本在包元数据、备份信封与最新版本记录中一致。
31. 应用销毁必须幂等释放根节点/窗口事件、存储订阅、跨标签监听、周期计时器和待处理提示定时器；销毁后的外部存储事件不得再次投影旧实例。
32. 离线外壳安装使用 Cache API 原子批处理；任一网络响应或缓存写入失败时整批不得可见，旧服务工作线程和完整缓存继续承担回退。激活只清理本应用旧版本缓存。
33. 导航与已知运行时资源采用 network-first/stale-if-error：网络 200 优先且缓存刷新只尽力执行，404/5xx 或网络异常回退已有规范 URL 缓存；未知且未缓存资源保留原 HTTP 失败。
34. 复航资源只接受不含凭据的 HTTP(S) URL，原文和解码目标不得含 ASCII/双向/不可见控制码，规范化前后均不超过 2,048 字符；外链使用独立标签、断开 opener 并提供明确可访问名称。
35. 本地服务器对所有响应统一设置最小权限 CSP、空摄像头/麦克风/定位权限、同源资源策略与防嵌入头；白名单仍是可公开文件的最终边界。
36. 所有导入与持久化时间必须满足 `new Date(Date.parse(value)).toISOString() === value`，即规范 UTC、固定毫秒精度；自然语言、地区格式、时区偏移和省略毫秒的可解析字符串仍视为无效。
37. 新写入时间取“系统当前时间与业务锚点中的最大值”：工作区元数据不早于上一修订，项目变化不早于自身更新时间，会话证据/检查点不早于会话与项目锚点，解决时间不早于原记录；系统时钟回拨不得制造倒序证据。
38. 严格导入验证跨记录因果区间：来源检查点不晚于接续会话开始，结束检查点与会话内轨迹/检查点落在开始和可选结束之间，解决时间不早于记录，活动会话不含结束检查点。
39. 所有持久化提交的修订号为 `max(当前修订, 来稿修订) + 1`；外部有效状态只有修订号严格前进时才采用。主键被显式移除时生成更高修订号的空工作区，避免版本序列归零。
40. 存储监听同时处理主键事件与 `key === null` 的全量清空事件，并在浏览器提供 `storageArea` 时校验事件来源，避免遗漏 `localStorage.clear()` 或误采用其他存储区事件。
41. 跨标签状态采用同时要求修订号严格增加且工作区 `updatedAt` 不早于当前状态；高修订号不能成为时间倒退的旁路。
42. 本地容量展示遍历当前来源的存储键值，按 DOM Storage 的 UTF-16 字符估算整个来源及 `reentry-deck/` 自有占用；以 5 MiB 作为明确标注的保守参考线而非伪造浏览器真实配额，80%/100% 分级预警。
43. 50,000 条总记录安全上限属于基础状态不变量，导入、替换和本地更新在持久化前共享该边界；超限时先返回单一容量错误，不遍历异常大的记录集合。
44. 哈希路由只接受 `#/`、`#/archive`、`#/settings` 与单段 `#/project/:id`；项目段在解码前后分别受 2,400/200 字符上限约束，畸形编码、控制字符、额外段和未知路由统一进入未找到页。
45. 严格备份要求工作区创建时间不晚于更新时间；项目更新时间不早于创建时间，项目自身辅助时间及所属会话、轨迹、检查点均落在项目创建—更新窗口。快速停靠并接续时，元数据时间推进到晚 1 ms 的接续会话开始。
46. Service Worker 的在线导航与外壳资源请求使用 4 秒 `AbortController` 超时；超时与网络异常共享缓存回退，成功/失败路径都清理计时器，避免弱网悬挂和长期资源泄漏。
47. 本地服务端口只接受去除首尾空白后的完整十进制 0–65535；白名单文件的 `stat` 失败统一转为 404，GET/HEAD 与文本错误都返回准确 `Content-Length`，避免宽松配置和探测竞态终止服务。
48. 复航缺口完全由当前派生证据生成，不写入状态：优先提示未收拢会话与快速停靠复核，再指出缺少摘要、下一动作、可靠检查点或材料入口；完整卡片不显示空提示框。
49. 快速检查点复核要求提交时目标仍是该项目的最新快速检查点，并拒绝摘要/下一动作的“未记录”占位；保存为 `sessionId: null` 的新人工检查点，原会话结束检查点及历史记录保持不变。
50. 复航索引与时间线按时间倒序；合法时间相同则以状态数组中更晚的插入为更新证据。界面开始会话和复核检查点必须复用该索引，不能自行定义“最新”排序。
51. `AppStore.update()` 在序列化前执行与导入候选相同的严格内容、引用、枚举和因果时间校验；配额与多标签保护之前不得产生一份“当前可写、重启即损坏”的本地主数据。
52. 轨迹是原始证据，项目动作和快速检查点是受字段上限约束的派生投影；超长投影以省略号明确压缩而不改写原轨迹，快速停靠的未决事项只收集尚未解决的问题与阻塞。

## 数据持久化

主键为 `reentry-deck/state/v1`，内容带单调递增的 `meta.revision`。每次成功写入后尽力保存前一版本；浏览器配额不允许第二份完整副本时，主写入仍然成立。若已有滚动快照阻塞主数据增量，程序只在配额异常下释放它并重试一次，同时要求尽快导出；其他错误绝不借机清理。前一版本可用于一次可逆撤销，但长期可靠恢复仍依靠用户导出的 JSON 信封。新信封携带内容校验码，导入时在结构检查前核对；旧信封和原始状态保持兼容。严格导入上限为 50,000 条记录，字段长度与界面输入上限一致，详细错误最多展开 50 项。

跨标签页通过 `storage` 事件接收新版本，并以持久化原文比较作为最终覆盖保护；即使事件延迟，过期标签也无法静默覆盖新数据。订阅事件同时标记 `local` / `external` 来源，使界面只在外部投影刷新时以内存方式保留正在编辑的普通对话框。

## 离线策略

安装时事务式预缓存完整外壳。在线导航和运行时资源使用网络优先并更新缓存，因此代码变化不会因忘记修改缓存编号而长期滞留；断网时回退到最后一次完整缓存。新增核心模块时仍应同步加入预缓存清单，以保证首次安装后的完整离线能力。
